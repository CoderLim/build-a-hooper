理解 **Build a Hooper 计算逻辑**，可以帮助你正确阅读一张球员卡，而不是只盯着 OVR。游戏会先把十三项属性整理成得分、组织、防守、篮板、身体和关键球等能力，再根据位置职责计算这套 Build 的适配程度。之后，球员影响力会与生涯球队强度、对手强度以及有限的比赛波动共同作用，形成完整的 82 场常规赛、个人数据、奖项和季后赛结果。

本页只介绍 Build a Hooper 计算逻辑的大方向，不公开每一个系数、阈值、随机细节或完整性校验方式。这样既能让玩家理解为什么某些 Build 更稳定，也不会把游戏变成照着公式抄答案的工具。

还不熟悉操作流程，可以先阅读 [Play Guide](/how-to-play)；想了解每个缩写的含义，可以打开 [Attribute Guide](/attributes)。

## Build a Hooper 计算逻辑概览

一局游戏大致经过以下几层处理：

1. 确认十三个属性槽都已完成，并且每轮选择有效。
2. 把单项属性组合成得分、组织、防守、篮板、身体和关键球能力。
3. 根据 PG、SG、SF、PF 或 C 的职责评估位置适配。
4. 将球员影响力与生涯球队、当场对手的强度结合。
5. 逐场模拟常规赛胜负和个人数据。
6. 更新战绩、排名、奖项竞争与季后赛资格。
7. 按系列赛继续模拟季后赛，最终生成球员卡和排行榜成绩。

Build a Hooper 计算逻辑并不只问“十三项等级平均有多高”，还会问“这些能力是否组合成了一个能完成位置任务的球员”。

## 十三项属性如何变成球员能力

每一局 Build a Hooper 都使用同一套属性：

**3PT · MID · FIN · DNK · HAN · PAS · PDEF · IDEF · BLK · REB · ATH · STR · CLU**

这些属性不会各自独立决定一场比赛，而会组成更接近篮球角色的能力组。

| 能力组   | 主要属性                          | 大致作用                     |
| -------- | --------------------------------- | ---------------------------- |
| 得分     | 3PT、MID、FIN、DNK、HAN、ATH、CLU | 投篮、突破、终结与稳定得分   |
| 组织     | PAS、HAN、CLU、ATH                | 控球、传球和为队友创造机会   |
| 外线防守 | PDEF、ATH、STR、CLU               | 跟防、对抗和外线干扰         |
| 内线防守 | IDEF、BLK、STR、REB               | 护框、封盖、卡位和禁区对抗   |
| 篮板     | REB、STR、ATH、IDEF               | 抢下投丢的球并结束防守回合   |
| 身体     | ATH、STR                          | 速度、爆发、对抗与角色承载力 |
| 关键球   | CLU                               | 高压阶段的执行和稳定性       |

因此，一个 A+ 属性只能创造明确优势，不能自动补齐其他工作。A+ 三分能提高得分威胁，但不会直接变成传球、篮板或护框；A+ 封盖能提升禁区威慑，但如果 REB 和 STR 很差，球队仍可能无法结束防守回合。

NBA 官方的 [数据术语表](https://www.nba.com/stats/help/glossary)会把助攻、篮板等产出分开统计，Jr. NBA 的 [位置介绍](https://jr.nba.com/basketball-positions/)也强调后卫、前锋和中锋承担不同职责。Build a Hooper 计算逻辑借用了这些通用篮球概念，但它仍然是一套轻量、虚构的游戏模拟，不是官方联盟模型。

## 为什么位置适配很重要

同样一套属性放在不同位置上，价值不会完全相同。Build a Hooper 计算逻辑会按照位置职责重新理解能力组合。

- **PG** 更重视 HAN、PAS、外线防守，以及足够迫使防守回应的得分能力。
- **SG** 更强调稳定得分、持球支持和外线防守。
- **SF** 需要更全面的侧翼能力，可以在得分、防守、身体与次级组织之间形成多种路线。
- **PF** 更依赖篮板、内线防守和身体，同时可以走空间型或终结型路线。
- **C** 通常需要优先完成护框、篮板、力量与篮下终结，再发展传球或三分等特色。

这并不代表每个位置只有一种标准答案。传球中锋、防守型控卫、空间型大前锋都可以成功，但特色必须建立在基本职责之上。

两个 OVR 接近的球员可能得到不同战绩，往往就是因为位置适配不同。组合合理的 Build 能把更多属性转化为场上影响力；组合松散的 Build 可能拥有很多高等级，却缺少一个完整角色。

## OVR 为什么不是全部答案

页面展示的 OVR 是十三项属性的直观摘要，它仍然很重要，因为高 OVR 通常意味着短板更少。但 OVR 不是 Build a Hooper 计算逻辑的唯一输入。

模拟还会根据得分、组织、防守、篮板、身体和关键球计算位置适配，再把 OVR 与位置适配组合成更接近实际作用的影响力。这样可以避免“只要平均分高就自动赢球”。

看最终球员卡时，可以按以下顺序判断：

1. 这名球员是否有可靠的主要得分方式？
2. 是否能处理球、传球，或者至少不破坏进攻？
3. 是否能完成该位置对应的防守任务？
4. 篮板和身体是否足以支撑角色？
5. 关键球属性是否建立在一个完整技能结构上？

一套角色清晰、位置合适的 Build，可能比平均等级略高但方向混乱的 Build 打出更稳定的赛季。

## 球队强度与对手强度如何进入模拟

自建球员不会独自决定整个赛季。Build a Hooper 计算逻辑还会估算生涯球队主要轮换的整体质量，并把它与当场对手的强度比较。

强队能提供更好的基础环境，但不会保证 82–0；弱队会让争冠更困难，但优秀球员仍然可以显著提高胜率。赛程中的对手强弱也会变化，因此不会把同一个固定胜率机械地使用 82 次。

这意味着选到什么生涯球队同样重要。你需要同时阅读“球员有多强”和“这名球员被放进了什么环境”。

## 单场胜负如何形成

每场比赛会从一个中性的竞争基础开始，再由以下因素调整：

- 自建球员的综合影响力；
- 生涯球队相对对手的强弱；
- 防守能力；
- 关键球能力；
- 保留比赛不确定性的有限波动。

Build a Hooper 计算逻辑会限制概率范围，所以顶级 Build 也不会场场必胜，较弱 Build 也仍然可能爆冷。属性应该明显改变长期结果，但比赛不能完全失去悬念。

同一局完成后的核心结果是可复现的。逐场模拟、直接模拟到赛季结束或观看 GameCast，目的都是以不同方式展示同一套权威结果，而不是不断刷新直到出现想要的战绩。

## 得分、助攻和篮板怎样生成

个人数据来自与角色最相关的能力组。

**得分**主要受得分能力、综合影响力和位置使用率影响。SG 通常承担更多得分回合，但高得分能力的 C 仍然可以超过普通后卫。

**助攻**主要受组织能力和位置影响。PG 的基础组织职责更高，但 PAS、HAN 出色的前锋或中锋也能得到不错的助攻数据。

**篮板**主要受 REB、身体能力和位置影响。C、PF 天然承担更多篮板任务，后卫则需要非常突出的篮板属性才能达到相似水平。

单场数据会围绕预期值上下波动，所以同一名球员会出现高光、低迷和正常比赛，但长期平均仍然与 Build a Hooper 计算逻辑中的能力结构保持联系。

## 为什么必须模拟 82 场

一场比赛的偶然性很大，82 场赛季能让一套 Build 的正常水平逐步显现。赛季过程中，系统会持续更新胜负、排名、得分、助攻、篮板、三双、奖项竞争和季后赛资格。

完整赛季更偏爱可重复的优势。双向、结构完整的球员通常能应对更多类型的对手；单一能力极强的球员可能在有利对位里爆发，也可能在短板被针对时迅速掉队。

因此不要只用某一场 GameCast 判断 Build。战绩、个人产出、奖项、季后赛路径和最终结果应该一起看。

## 奖项不是只看 OVR

Build a Hooper 计算逻辑会把个人数据、对应能力、综合影响力和球队成绩结合起来。

- 得分王需要足够强的得分能力和赛季得分产出。
- MVP 需要高影响力、全面产出以及成功的常规赛。
- DPOY 需要真正出色的防守能力和足够的球队胜场。
- Finals MVP 需要球队夺冠，同时球员拥有足以驱动争冠的影响力。

这样可以避免纯进攻高 OVR 球员自动拿到 DPOY，也避免刷出漂亮数据但球队长期失败的球员自动获得 MVP。

## 季后赛如何计算

常规赛胜场决定能否进入季后赛，以及从附加赛还是首轮开始。季后赛继续使用球员影响力、球队强度、对手强度、防守和关键球等核心因素，但每场比赛会进入系列赛记录。

附加赛需要赢下关键一场，标准轮次则需要赢得七场四胜制系列赛。系统会保留胜负顺序，因此真正从 1–3 落后完成逆转，和普通打满七场并不是同一件事。

总冠军必须通过每一轮，不会因为常规赛排名高就直接获得。

## 这套计算逻辑没有模拟什么

Build a Hooper 是策略游戏，不是现实 NBA 比赛预测器。Build a Hooper 计算逻辑不会逐回合模拟所有战术、教练调整、伤病、换人、疲劳、合同、裁判判罚或真实阵容化学反应。

它把篮球概念压缩成一套玩家容易理解的循环：十三项属性、五个位置、球队环境、82 场赛季和季后赛。目标是让选择与结果之间存在清晰联系，同时保留重玩价值，而不是声称能够精确预测真实球员生涯。

## 怎样利用计算逻辑改进选秀

玩 Build a Hooper 时不需要计算公式，只要使用一份简单清单：

1. 先确定位置必须完成的工作。
2. 优先完成一个主要能力组，不要只收集最高字母。
3. 增加第二种贡献方式。
4. 在最后几轮前修复一个致命短板。
5. 只有当前球队无法支持关键空槽时再使用重随。
6. 揭晓后先看角色和位置适配，再看 OVR。
7. 用完整赛季验证最初的 Build 计划。

例如，PG 通常先完成 HAN、PAS，再补得分和 PDEF；C 通常先完成 REB、IDEF，再根据路线补 FIN、STR、ATH、PAS 或 3PT。更具体的方案可以查看 [Position Builds](/best-builds)，模式差异则见 [Game Modes](/modes)。

## Build a Hooper 计算逻辑常见问题

### 最高 OVR 一定赢得最多吗？

不一定。OVR 有明显优势，但位置适配、球队强度、对手、防守、关键球和合理波动都会影响完整赛季。

### 一个 A+ 属性能带动整套 Build 吗？

它可以定义特色，但不能替代整个能力组。HAN 与 PAS、IDEF 与 REB、投射与持球等互补组合通常更稳定。

### 为什么相似 Build 会得到不同战绩？

细微属性差异可能改变位置适配和影响力，生涯球队、赛程对手和有限比赛波动也会改变具体胜负。

### GameCast 会重新计算比赛吗？

不会。GameCast 主要把同一场比赛按节展示，不是额外重随结果的入口。

### 奖项只由个人数据决定吗？

不会。奖项还会参考对应能力、球员影响力和球队成功程度。

### 会公开完整公式吗？

本页公开影响结果的主要方向，但不会公布所有系数、阈值、随机细节和完整性控制。
