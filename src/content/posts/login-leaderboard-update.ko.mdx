최근 업데이트에서는 출시 이후 가장 큰 게임 주변 기능을 추가했습니다. **계정, 누적 Legacy 리더보드, 그리고 플레이한 런을 저장하기까지의 더 자연스러운 흐름**입니다. 무엇이 바뀌었고 어떻게 사용할 수 있는지 정리합니다.

## 먼저 플레이하고, 필요할 때 로그인하세요

Build a Hooper는 계속 **게스트 우선** 게임입니다. 계정 없이도 드래프트하고, 선수를 만들고, 시즌을 시뮬레이션하고, **My Card**까지 진행할 수 있습니다.

로그인이 주는 가장 분명한 이점은 하나입니다. **완료한 시즌을 클라우드에 저장하고 리더보드 기록에 반영할 수 있습니다.**

| 기능                       | 게스트 | 로그인 |
| -------------------------- | ------ | ------ |
| 전체 게임 루프             | 가능   | 가능   |
| 같은 브라우저에서 이어하기 | 가능   | 가능   |
| My Card 공유 / 다시 플레이 | 가능   | 가능   |
| 시즌 종료 후 런 저장       | 불가   | 가능   |
| Legacy 포인트 및 순위      | 불가   | 가능   |

로그인하지 않은 상태로 런을 끝내면 My Card에서 결과를 제출하기 위한 로그인 안내가 표시됩니다. 카드 공유와 다시 플레이 같은 나머지 기능은 그대로 사용할 수 있습니다.

## Legacy 리더보드 — 한 번의 최고점이 아닌 누적 기록

새로운 [/leaderboard](/leaderboard)는 한 시즌의 최고 기록만 보는 대신, 저장된 모든 런에서 쌓인 장기 점수인 **Legacy**로 플레이어를 정렬합니다.

다음 기준으로 정렬할 수 있습니다.

- **Legacy 포인트** — 기본 정렬
- **우승 횟수**
- **승률**
- **최고 OVR**
- **총 런 수**
- **총 수상 횟수**

플레이어를 선택하면 **프로필**에서 커리어 누적 기록을 볼 수 있습니다. 꾸준히 플레이하는 사람, 우승을 모으는 사람, 다양한 빌드를 실험하는 사람 모두 목표를 가질 수 있도록 설계했습니다.

## 런이 저장되는 과정

로그인한 상태에서 시즌을 마치고 **My Card**에 도달하면 다음 과정이 진행됩니다.

1. 클라이언트가 모드, 포지션, 빌드 슬롯, 시즌 기록을 바탕으로 런 데이터를 만듭니다.
2. 데이터가 `/api/hooper/runs`로 전송됩니다.
3. 서버가 런을 저장하고 Legacy 기록의 포인트, 승수, 우승 횟수 등을 업데이트합니다.

같은 런을 새로고침으로 중복 제출하지 않도록 브라우저에서 중복 저장을 방지합니다.

## 게임과 맞춰진 내비게이션

[Play](/#play)에서도 홈페이지와 같은 헤더를 사용하도록 사이트 내비게이션을 통일했습니다. **플레이**, **리더보드**, 각종 가이드, 로그아웃 상태의 로그인·회원가입 링크를 어디서든 같은 위치에서 찾을 수 있습니다.

게임 내부 바는 주로 **재시작** 기능만 남겨 더 얇게 만들었습니다. 플레이 중 중복 메뉴가 차지하던 세로 공간도 줄었습니다.

## 로그인 흐름 개선

초기 테스트에서 자주 나온 두 가지 불편을 수정했습니다.

**로그인 뒤 설정 화면으로 이동하지 않습니다.** 회원가입이나 로그인 후에는 일반 계정 대시보드가 아니라 사용자가 출발한 홈페이지, 게임, 리더보드로 돌아갑니다.

**운영 도메인 인증 설정을 수정했습니다.** 배포된 인증 설정과 실제 도메인이 다를 때 [buildahooper.org](https://buildahooper.org)에서 가입을 막던 `Invalid origin` 오류를 해결했습니다.

## 운영 반영 전 스테이징 검증

새 기능은 별도의 스테이징 Worker와 데이터베이스에서 먼저 검증한 뒤 운영에 반영했습니다. 현재 [buildahooper.org](https://buildahooper.org)에는 위 기능이 모두 포함되어 있습니다.
